# 创业项目答辩演示说明

## 最终验收补充（2026-10-04）

标准业务演示路径：`/dashboard` → 新增文物 → 上传有效 JPEG/PNG/WebP → 名称“青铜鼎”、朝代“商代”、材质“青铜” → 粘贴有依据的馆藏文字 → 保存草稿 → 开始 AI 分析 → 生成 AI 讲解 → 进入人工审核 → 修改一句并保存 → 审核通过 → 发布 → 查看游客展示页。四版均审核后四个游客标签才都有内容；只审核一版则其他标签禁用，不泄露草稿。

本次浏览器实测从填写资料至游客页约 71 秒，无明显报错或白屏。该计时不包括尚未实现的资料文件上传与授权确认，不能据此称完整 17 项全部通过。现有文字输入不是文件上传，PENDING 授权字段也不是确认授权。答辩必须如实说明。

真实密钥配置后 AI 断连请进入专用 `/demo`，不要声称普通真实 AI 功能自动无损降级。专用演示固定 Mock，八步均可完成。无密钥正常业务也可通过模拟稿完成，但模拟类别、视觉描述明确不是真实识别。

五分钟建议：准备30秒、资料与知识卡60秒、四版与人工审核90秒、发布与游客页60秒，保留60秒问答/恢复。首次安装不计入演示且必须预先完成。`pnpm test:mvp` 验证隔离的无密钥、DEMO_MODE 和断连演示三种配置；自动测试耗时不是人的操作时间。

## 演示准备

进入项目目录 `D:\Codex\projects\MuseumAI-Studio`，启动 ` .\frontend\run-local.ps1`，打开 `http://localhost:3000/demo`。不需要 Docker 或 Python 后端。

首次安装依赖、生成 Prisma 客户端及执行数据库迁移需在断网前完成。离线演示仍需要本机网页服务与 SQLite 数据库正常运行，不依赖互联网、AI API、PDF 服务或外部图片。

建议在前端环境文件中设置 `DEMO_MODE=true`。演示接口始终直接使用 MockAIProvider，即使全局配置了真实模型和密钥也不会访问外部 AI；其他业务遵循原有 Provider 配置。

## 三分钟答辩脚本

- 0:00—0:30：打开演示区，说明“演示数据，仅用于产品功能展示。”选择青铜鼎、青花瓷瓶或陶俑。图片是本地示意图，不是真实馆藏照片。
- 0:30—1:10：点击“开始演示”。依次展示上传、读取资料、模拟图片分析、自动标签、知识卡及四种讲解。每步约 0.8 秒视觉延迟，不伪装成真实识图。
- 1:10—2:00：查看知识卡、模拟置信度、来源资料及四种讲解。强调年代、出土地等未提供的信息不会编造。展开讲解，确认内容后点击“我已核对讲解，确认审核并发布”。系统不会自动批准 AI 草稿。
- 2:00—2:40：点击“进入游客展示页”。浏览实际 `/exhibit/[id]` 页面、图片和四种已审核讲解标签页；游客看不到后台控制按钮。
- 2:40—3:00：返回演示区，展示“重置演示”，说明流程支持重复演示，也可切换另外两件样本。

## 重复演示与恢复

打开页面自动幂等初始化三个固定编号的样本，重复进入不会复制数据或覆盖已经完成的进度。进度保存在 SQLite，刷新后点击继续即可。步骤请求支持安全重试，不重复生成讲解或审核记录。

“重置演示”重置全部三个演示样本，清理其讲解、元数据、来源及处理记录，然后重新创建来源与初始进度。只处理独立演示馆的固定样本，不删除正常馆藏。重置后游客链接暂时不可访问，重新审核发布后恢复。

若本地数据库或网页服务不可用，页面给出中文错误，可修复后继续或重置；外部网络、AI API 和 PDF 服务故障不影响演示。

## 演示数据边界

预置类别、材质、器型、纹样和标签是明确标记的模拟资料，不是模型识别事实。模拟置信度 50% 仅用于展示界面，不代表准确率。所有生成讲解使用本地来源并保存来源关联；人工确认、发布与分析事件写入处理记录。本模式用于答辩展示，不应作为真实馆藏鉴定或正式审核结果。
